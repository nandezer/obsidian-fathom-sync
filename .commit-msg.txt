fix: v2 hotfix from post-publish review

Addresses findings from the security + code-quality reviews run after
pushing 1b93263. No CRITICAL, but one HIGH ships an insecure-by-default
Worker template.

Worker
- wrangler.toml no longer declares PLUGIN_BEARER_TOKEN or
  FATHOM_WEBHOOK_SECRET as [vars]. Users MUST set both via
  wrangler secret put / Cloudflare secrets store. The Worker now
  fails closed with HTTP 503 worker_not_configured when either is
  missing (except /health). Previously a click-deploy without the
  manual secret step would run with the literal string
  set-me-at-deploy-time as both the bearer token and HMAC key.
- The 500 catch-all no longer echoes err.message to unauthenticated
  callers (minor information disclosure).
- verifyFathomSignature split into readSignatureHeaders +
  computeExpectedSignature so each function fits the 50-line budget.
  Constant for MAX_TIMESTAMP_SKEW_SECONDS extracted.

Plugin
- Connect-button onClick extracted from settings.ts into three private
  methods: handleConnectWebhook, registerWebhook, surfaceSigningSecret.
  Was 95 lines, now each under 50.
- runSync extracted helpers drainQueueIfConfigured and
  surfaceForeignNotesWarningOnce + a module-level mergeSyncResults
  utility. Was 65 lines, now under 50.
- Bearer-token input rendered as type=password so the value is masked
  in the settings UI (screen-share, shoulder-surfing).
- Clipboard fallback for the signing secret now uses logger.warn
  instead of a bare console.info call, so it respects the project's
  log abstraction.

Docs
- WEBHOOKS.md updated end-to-end to reflect the secrets-store deploy
  flow. New 503 case documented in troubleshooting.
